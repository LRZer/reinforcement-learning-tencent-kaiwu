# 腾讯开悟强化学习比赛：PPO 峡谷追猎智能体

[English](README.en.md) · [技术详解](docs/method.zh-CN.md) · [成绩与证据](docs/results.zh-CN.md) · [数据清单](data/README.md)

本项目参加第十七届中国大学生服务外包创新创业大赛东部区域赛人工智能专项赛道，在腾讯开悟 `gorge_chase`（峡谷追猎，课程报告称“峡谷寻宝”）环境中训练鲁班七号智能体。目标是在怪物追击下收集宝箱、延长生存，并决定何时使用加速 BUFF 和闪现。

方案由 **PPO、六分支 MLP、局部地图 CNN、动态门控融合、BFS 特征和显式记忆**组成。每步将环境观测与已积累信息编码为状态，策略网络选择动作，训练端根据整局轨迹更新策略与价值估计。历史记录为 **初赛 37/158 名、打榜平均分 997.15、区域三等奖**；统计口径和证据见[比赛结果](#7-比赛结果与模型记录)。

## 1. 任务与技术挑战

英雄在 **128 × 128** 栅格地图中行动，每帧获得以自身为中心的 **21 × 21** 局部地图。两只怪物陆续追击；宝箱直接加分，BUFF 暂时提升移速，闪现可跨越地形并进入冷却。每个决策步执行一个离散动作。

<img src="docs/evidence/environment-map.png" width="440" alt="赛题说明中的地图示意：英雄、怪物、障碍与资源分布">

地图示意取自[原始赛题说明](docs/reports/task-guide.pdf)第 2 页。按第 3–9 页计分规则，单局分数为：

$$S = 1.5 \times \text{存活步数} + 100 \times \text{收集宝箱数}.$$

| 技术问题 | 已实现的处理方式 |
|---|---|
| 局部视野难以持续保留目标信息 | 缓存曾见宝箱与 BUFF 点位，记录已探索区域、访问热度和近期行为 |
| 直线距离难以反映障碍和局部连通性 | 8 邻域 BFS、方向可达区域比例、拓扑摘要及地图 CNN |
| 收集资源与避险需要同时决策 | 分别编码怪物、资源和地形，用门控组合上下文，按风险设置条件奖励 |
| 更新策略时需利用回报并保留探索 | GAE 优势估计、PPO 策略/价值剪切、熵正则、优势标准化与梯度裁剪 |

环境提供 10 张开放地图与 5 张隐藏评测地图。归档配置按顺序使用地图 1–8 训练，9、10 作留出地图轻量验证；隐藏地图由比赛平台提供。表中描述实现和设计目的，模块贡献的量化结果属于[证据范围](#8-实现边界与证据范围)。

## 2. 技术流程

![采样、优化、模型同步与留出地图验证流程](docs/figures/workflow.zh.svg)

| 阶段 | 数据如何流动 | 对应实现 |
|---|---|---|
| ① 形成状态 | 新局清空记忆；读取英雄、怪物、资源、地图和技能状态，更新缓存与历史，形成 3601 维观测及独立的 16 维动作掩码 | [预处理器](agent_ppo/feature/preprocessor.py)、[观测展平](agent_ppo/feature/definition.py) |
| ② 选择动作 | 网络输出 16 个动作 logits 和 1 个状态价值；结合掩码形成动作概率，训练随机采样 | [网络](agent_ppo/model/model.py)、[智能体](agent_ppo/agent.py) |
| ③ 执行与反馈 | 环境执行动作；处理下一帧时，根据得分、怪物距离、地形、资源与结束状态的变化计算奖励 | 预处理器、[训练工作流](agent_ppo/workflow/train_workflow.py) |
| ④ 整理轨迹 | 保存状态、掩码、动作、奖励、done、旧价值与完整旧概率分布；对局结束后向后递推 GAE | [样本与 GAE](agent_ppo/feature/definition.py) |
| ⑤ 优化与同步 | 轨迹送至平台样本池；Learner 取样、执行 PPO 更新并同步模型，采样端在新局开始加载 `latest` | [PPO 优化](agent_ppo/algorithm/algorithm.py)、[平台配置](conf/configure_app.toml) |
| ⑥ 轻量验证 | 暂停训练采样，复用同一环境切换至地图 9、10，取最大概率动作；验证轨迹仅用于 `val_*` 统计 | 训练工作流 |

一次动作决策经过“观测 → 特征/记忆 → 网络 → 掩码后概率 → 动作”。梯度更新发生在 Learner 端，利用采样时保存的概率与价值计算训练目标。验证每轮共 4 局，间隔配置为 600 秒；因初始计时为 0，首轮可在首个训练局后触发。验证不发送训练样本，也不调用梯度更新。

## 3. 状态表示与显式记忆

### 3.1 输入组成

总输入为 **73 维结构化特征 + 3528 维地图 = 3601 维**。动作掩码单独传给概率处理与样本记录。特征按各字段的参考尺度归一化，部分字段有截断，完整字段定义见[特征布局](data/metadata/feature_schema.json)。

| 分支 | 维度 / 展平切片 | 信息及用途 |
|---|---|---|
| 英雄 | 14 / `[0:14]` | 位置、进度、得分、宝箱数、闪现可用性与冷却、移速及怪物阶段信息 |
| 怪物 | 16 / `[14:30]` | 两个怪物槽位，每个包含存在、可见性、相对位置、欧氏距离、速度、相对方向与距离桶 |
| 宝箱 | 14 / `[30:44]` | 可见/缓存比例、可见目标 BFS 距离、缓存目标欧氏距离与置信值、未知区域距离 |
| BUFF | 8 / `[44:52]` | 效果计时、可见或缓存目标位置与距离、上一动作是否闪现及闪现次数 |
| 拓扑 | 13 / `[52:65]` | 开阔度、障碍密度、邻格通路比例、死胡同、贴墙程度及八方向可达比例 |
| 记忆 | 8 / `[65:73]` | 重访、位置多样性、无位移、位移大小、探索目标方向、未知比例与无进展标志 |
| 局部地图 | 3528 / `[73:3601]` | `8 × 21 × 21` 空间张量，由 CNN 编码 |

地图八通道依次为：**通路、障碍、英雄、怪物、可见宝箱、可见 BUFF、访问热度、危险热度**。地图危险热度在怪物周围 7×7 内按距离指数衰减，重叠处取最大值；奖励使用另一个由怪物距离与速度计算的标量危险度。

### 3.2 局部 BFS 与目标信息

BFS（广度优先搜索）从局部地图中心按等代价八邻接计算可达距离，用于可见宝箱排序。每个方向另从相邻第一格搜索，得到“可达格数 / 局部通路格数”。开阔度、死胡同和贴墙等摘要为策略提供地形信息。

可见宝箱按 BFS 距离与候选价值排序，缓存宝箱按欧氏距离选择；BUFF 优先取可见目标，其次取缓存点。怪物与 BUFF 的 BFS 距离还用于诊断和奖励。BFS 和目标选择结果作为特征输入，最终移动或闪现由网络决定。

### 3.3 记忆如何更新

| 记忆 | 更新规则 | 保留的信息 |
|---|---|---|
| 宝箱缓存 | 每次预处理 `×0.995`；可见目标置 1，候选阈值 `>0.35`；拾取后清除英雄周围 3×3 | 曾观察到、尚未清除的宝箱位置与衰减值 |
| BUFF 点位 | 看到后在本局保留位置 | 可再次刷新资源的点位；点位存在不等于资源当前可拾取 |
| 访问热度 | 每次 `×0.97`；当前位置 `+0.35`，上限 1 | 近期常到区域，裁剪成局部地图通道 |
| 行为历史 | 最近 20 个位置、12 个动作、6 次位移 | 重访、停滞、无进展与闪现历史 |
| 探索目标 | 最近缓存宝箱 → 最近缓存 BUFF → 最近未知格 | 指向后续可探索目标的方向特征 |

全局缓存采用 128×128 数组，只累积已经观察的信息。记忆由预处理器显式维护；网络处理的是包含记忆特征的当前输入。每局 reset 清空这些状态，预处理调用会推进缓存衰减与内部计时。

## 4. 模型架构与动作决策

![多分支编码、门控融合及 Actor-Critic 双头](docs/figures/architecture.zh.svg)

### 4.1 编码器

六类结构化输入各经过独立的两层 MLP（多层感知机）：`分支维度 → Linear32 → ReLU → Linear32 → ReLU`，均输出 32 维。地图 CNN（卷积神经网络）编码二维空间关系，其层级如下；形状省略批次维度。

| 地图编码阶段 | 输出形状 |
|---|---|
| 原始地图 | `8 × 21 × 21` |
| 3×3 Conv，16 通道 + ReLU | `16 × 21 × 21` |
| 3×3 Conv，32 通道 + ReLU | `32 × 21 × 21` |
| 2×2 最大池化 | `32 × 10 × 10` |
| 3×3 Conv，64 通道 + ReLU | `64 × 10 × 10` |
| 自适应平均池化至 1×1、展平 | `64` |
| Linear64 + ReLU | `64` |

卷积均使用 stride=1、padding=1；最大池化 stride=2。结构化分支输出实体与行为摘要，CNN 输出局部空间嵌入。

### 4.2 动态门控与融合

令英雄嵌入为 $h_h\in\mathbb{R}^{32}$，地图嵌入为 $h_m\in\mathbb{R}^{64}$。门控把两者拼接为 96 维，经 `Linear32 → ReLU → Linear5 → Softmax` 得到五个权重：

$$\alpha=\operatorname{softmax}(\operatorname{MLP}_{gate}([h_h,h_m])),\qquad c=\sum_{i=1}^{5}\alpha_i h_i.$$

其中 $h_i$ 依次对应怪物、宝箱、BUFF、拓扑和记忆嵌入；各为 32 维，权重非负且总和为 1，加权上下文 $c$ 为 32 维。门控权重由英雄/地图信息计算，各实体信息通过相应分支与地图通道参与后续决策。

融合直接拼接 **英雄32 + 地图64 + 上下文32 = 128 维**，经过两层 `Linear128 → ReLU`。英雄与地图既参与门控，也直接进入融合；五个上下文分支在此之前被加权汇总。

### 4.3 输出头与动作空间

| 输出 | 形状 | 用途 |
|---|---|---|
| Actor（策略头） | `128 → 16` logits | 给出动作偏好，掩码后转为概率，决定执行哪个动作 |
| Critic（价值头） | `128 → 1` | 估计后续折扣训练奖励，参与优势计算与价值学习 |

动作 **0–7** 依次为东、东北、北、西北、西、西南、南、东南移动；**8–15** 为对应八方向闪现。直向闪现参考距离 10，斜向 8。合法动作掩码主要反映技能可用性，普通移动被标为合法仍可能撞墙。训练从概率分布采样，轻量验证取最大概率动作。

![输入维度与模型参数分布](docs/figures/profiles.zh.svg)

网络共 **75,814 个参数**，归档权重包含 **44 个 float32 张量**并与现有网络严格匹配。各模块计数与张量形状见[权重信息](data/metadata/checkpoint_inspection.json)。Actor 与 Critic 共享编码和融合部分。

## 5. 奖励设计

训练奖励用来反馈动作后的得分、风险和行为变化；比赛计分使用第 1 节的环境分数。每步奖励由以下条件项相加。

![奖励塑形的条件事件增量](docs/figures/rewards.zh.svg)

| 类别 | 关键配置与条件 |
|---|---|
| 生存与资源 | `0.02 × 正步数得分增量`，普通存活步约 +0.03；每个宝箱 +1.20；拾取 BUFF +0.35 |
| 避险 | 距离增量系数 0.10、危险度下降系数 0.12、夹击缓解系数 0.08；步数 ≥500 或危险度 >0.55 时对这些项乘 1.3 |
| 地形 | 死胡同、贴墙系数分别为 -0.05、-0.02；开阔度超过 0.35 的部分系数 +0.03，均乘 `max(危险度, 0.25)` |
| 接近目标 | 宝箱接近系数 0.015：危险度 <0.35 且无宝箱收益；BUFF 接近系数 0.012：无效果、无本步资源收益、危险度 <0.55，且 BUFF 距离 ≤18、宝箱距离 >4 |
| 无效移动与徘徊 | 上一动作存在且位移 <0.1：-0.03；危险度 <0.35、无资源收益、10 个位置窗口首尾距离 <5：-0.10 |
| 终局 | 被捕获 -2.00；达到步数上限 +1.20；异常截断 -0.50 |

闪现按施放前风险分级，判定顺序为高危 → 中危 → 低危。令闪现参考距离为 $R$：

| 风险级别 | 获得正奖励的条件 | 满足 / 不满足 |
|---|---|---|
| 高危：危险度 ≥0.55 或最近怪物距离 ≤6 | 欧氏距离增加 ≥0.55R，或危险度下降 ≥0.25，或 BFS 距离增加 ≥0.60R | +0.20 / -0.12 |
| 中危：危险度 ≥0.30 或最近怪物距离 ≤10 | 欧氏距离增加 ≥0.35R，或危险度下降 ≥0.08，或 BFS 距离增加 ≥0.40R；并且开阔度增加 ≥0.05 | +0.08 / -0.04 |
| 低危 | 获得宝箱且当前危险度 <0.35 | +0.04 / -0.05 |

距离变化项有归一化与截断；地形项按危险度缩放。图中事件增量是配置值，一步可叠加多项。危险度定义、完整公式与参考阈值见[奖励塑形详解](docs/method.zh-CN.md#5-奖励塑形)。

## 6. PPO 优化与训练配置

### 6.1 从轨迹得到优势与价值目标

轨迹保留采样时的状态价值 $V_{old}$ 和完整动作分布 $\pi_{old}$。GAE（广义优势估计）从末步向前，结合即时奖励、下一状态价值与后续反馈，估计动作结果相对预期的差异：

$$\delta_t=r_t+\gamma(1-d_t)V_{old}(s_{t+1})-V_{old}(s_t),\qquad A_t=\delta_t+\gamma\lambda(1-d_t)A_{t+1}.$$

这里 $d_t$ 为结束标志，$r_t$ 为塑形奖励，$\gamma=0.99$、$\lambda=0.95$。价值回归目标为 $A_t+V_{old}(s_t)$，在代码中保存为 `reward_sum`。末步下一状态价值置零；捕获与所有截断均作为 done。优势在每个 Learner 批次内标准化。

### 6.2 策略、价值与联合损失

PPO（近端策略优化）比较所选动作在新旧策略下的概率，以优势调整动作概率，并用剪切目标限制过大概率变化产生的收益：

$$\rho_t=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{old}(a_t\mid s_t)},\qquad L_{policy}=-\mathbb{E}\left[\min\left(\rho_t A_t,\operatorname{clip}(\rho_t,0.8,1.2)A_t\right)\right].$$

Critic 拟合价值目标，启用价值剪切；熵 $H(\pi)$ 鼓励保留动作探索。联合损失为：

$$L=L_{policy}+0.5L_{value}-0.005H(\pi).$$

代码的 $L_{value}$ 自身已含 `0.5 × max(普通平方误差, 剪切价值平方误差)`。每个 512 条样本的 Learner 批次运行 4 轮，每轮随机打乱，再按 256 条的 mini-batch 更新；Adam 更新前的梯度范数裁剪上限为 0.5。完整样本字段与计算细节见[PPO 与样本](docs/method.zh-CN.md#4-ppo-与样本)。

### 6.3 归档配置与监控

| 环境设置 | 值 | 优化 / 采样设置 | 值 |
|---|---|---|---|
| 训练 / 轻量验证地图 | 1–8 / 9、10 | γ / GAE λ | 0.99 / 0.95 |
| 宝箱 / BUFF 数量 | 10 / 2 | Adam 学习率 | 3 × 10⁻⁴ |
| BUFF 刷新 / 闪现冷却 | 200 / 200 步 | 策略与价值剪切范围 | 0.2 |
| 第二怪物 / 怪物加速 | 200 / 300 步 | 熵系数 / 价值系数 | 0.005 / 0.5 |
| 单局步数上限 | 1000 | 更新轮数 / mini-batch | 4 / 256 |
| 验证局数 / 间隔 | 每轮共 4 局 / 600 秒 | Learner 批次 / 样本池容量 | 512 / 2048 |
| 模型同步 / workflow 保存间隔 | 60 / 1800 秒 | 样本池采样 / 移除 | Uniform / FIFO |

平台采用 MinSize 限流，预填充比例为容量的 0.5；这些是样本池配置。监控将环境分数、整局塑形奖励、存活步数、宝箱数及终局状态分开记录，优化侧记录损失、熵、概率比、剪切比例和梯度范数。指标含义见[指标字典](data/metadata/metrics.csv)，全部配置见[配置快照](data/metadata/configuration.json)。

归档模型为 [model.ckpt-34055.pkl](ckpt/model.ckpt-34055.pkl)，大小 316,415 字节，保存网络 `state_dict`；平台元数据的 `train_step` 为 34055，导出时间为 2026-04-27。报告称其为最终训练包，打榜截图未显示提交模型 ID，因此模型归档记录与成绩证据分别列示。该编号不解释为环境交互步数；完整信息见[模型记录](docs/results.zh-CN.md#检查点记录)。

## 8. 实现边界与证据范围

| 范围 | 现有代码 / 材料的具体含义 |
|---|---|
| 局部 BFS | 不可达或超出视野的目标回退距离为 20；对角搜索只检查目标格；方向搜索可返回中心，同一连通分量的方向分数可能相同 |
| 带状态的预处理 | 原始轻量验证对同一帧重复调用预处理，会重复推进缓存、计时和历史；正式平台评测使用另一工作流 |
| 环境与参考常量 | 实际配置在第 300 步加速怪物，部分阶段特征与奖励压力参考 500；10 个位置的徘徊窗口在每帧一次调用时跨 9 次位置变化 |
| 结构统计 | 输入维度、参数数、奖励事件图来自代码或权重静态检查；未保留逐状态门控权重 |
| 性能证据 | 已保留榜单平均分、名次与证书；未保留逐局分数、训练/验证曲线、隐藏地图分项成绩、硬件耗时记录和消融结果 |

因此各模块的独立增益、得分方差、闪现成功率和泛化提升均没有可量化记录。实现语义见[技术详解](docs/method.zh-CN.md#7-实现边界)，结果统计口径及图表来源见[证据说明](docs/results.zh-CN.md)。
