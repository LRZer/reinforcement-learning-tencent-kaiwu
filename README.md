# 腾讯开悟：PPO 峡谷寻宝智能体

[English](README.en.md) · [技术说明](docs/method.zh-CN.md) · [成绩证据](docs/results.zh-CN.md) · [数据清单](data/README.md)

本项目面向腾讯开悟 `gorge_chase`（峡谷追猎）比赛环境：控制鲁班七号在地图中收集宝箱、躲避怪物，并选择何时使用加速 BUFF 和闪现。策略使用 **PPO + 多分支 MLP/CNN + 动态门控**，结合局部 BFS、目标缓存和行为记忆处理寻宝与生存决策。

每一步，系统把附近地形、怪物、资源和近期行为转为特征，由神经网络给出移动或闪现动作；训练通过动作产生的奖励反馈更新策略。

比赛来源为**第十七届中国大学生服务外包创新创业大赛，东部区域赛人工智能专项赛道**。仓库归档竞赛代码、最终训练包中的模型、原始报告和赛题说明，并提供双语技术图表与结构化结果数据。

阅读顺序：[任务与计分](#任务如何计分) → [网络与输入](#网络与输入) → [奖励设计](#奖励设计) → [技术流程与训练](#技术流程与训练)。字段、公式与实现边界集中在[技术说明](docs/method.zh-CN.md)。

## 任务如何计分

英雄在 **128 × 128** 栅格地图中行动，每次观察以自身为中心的 **21 × 21** 局部区域。两只怪物陆续追击；宝箱提供得分，BUFF 暂时提高移速，闪现可穿越地形并进入冷却。

<img src="docs/evidence/environment-map.png" width="400" alt="赛题环境地图示意">

地图示意来自赛题说明第 2 页。

按[赛题说明](docs/reports/task-guide.pdf)第 3–9 页，单局得分为：

$$S = 1.5 \times \text{存活步数} + 100 \times \text{收集宝箱数}.$$

环境包含 10 张开放地图和 5 张隐藏评测地图。本地配置使用地图 1–8 训练，9、10 作轻量验证；隐藏地图由比赛平台提供。**训练奖励与比赛得分不同**：奖励还包含避险、地形、闪现质量和防徘徊等引导项。

这些是代码实现的功能；各模块对比赛分数的独立贡献尚无消融实验量化。

CNN 编码二维地形，BFS 提供绕开障碍的局部距离与连通性特征，缓存保留曾观察到的资源位置；动作最终由策略网络选择。宝箱缓存每次预处理衰减为原值的 0.995 倍，访问热度衰减为 0.97 倍，探索目标按“缓存宝箱 → 缓存 BUFF → 未知区域”选取。记忆由预处理器维护，网络每次处理包含这些记忆特征的当前观测；全局缓存只包含已观察信息。

## 网络与输入

![Actor-Critic 网络结构](docs/figures/architecture.zh.svg)

**Actor** 输出动作偏好，转换为概率后决定走哪个方向、是否闪现；**Critic** 输出状态价值，即对后续折扣训练奖励的估计，训练时用于判断动作结果相对预期好多少。二者共享前面的编码与融合网络。

| 输入分支 | 维度 | 内容 |
|---|---:|---|
| 英雄 | 14 | 位置、进度、得分、技能冷却、移速等 |
| 怪物 | 16 | 两只怪物的存在、可见性、相对位置、距离和速度等 |
| 宝箱 | 14 | 可见目标 BFS 距离、缓存目标欧氏距离、探索边界等 |
| BUFF | 8 | 效果计时、可见或缓存目标、闪现历史等 |
| 拓扑 | 13 | 开阔度、障碍密度、分支、死胡同、贴墙、8 方向可达比例 |
| 记忆 | 8 | 重访、位置多样性、位移、探索方向及无进展标志 |
| 局部地图 | 3528 | `8 × 21 × 21`：通路、障碍、英雄、怪物、宝箱、BUFF、访问热度、危险度 |

从输入到输出的层级如下，张量形状省略批次维度：

| 阶段 | 层与形状 | 作用 |
|---|---|---|
| 结构化编码 | 6 个独立 MLP，各自 `输入维度 → 32 → 32`，每层接 ReLU | 分别编码英雄、怪物、宝箱、BUFF、拓扑与记忆 |
| 地图编码 | `8×21×21 → Conv16 → Conv32 → MaxPool2 → Conv64 → 全局平均池化 → Linear64` | 卷积均为 3×3、padding=1，卷积与投影后接 ReLU；最大池化后空间为 10×10，最终输出 64 维 |
| 动态门控 | `英雄32 + 地图64 → Linear32 → ReLU → Linear5 → Softmax` | 生成总和为 1 的五个权重；怪物、宝箱、BUFF、拓扑、记忆嵌入加权求和为上下文32 |
| 融合 | `英雄32 + 地图64 + 上下文32 → 128 → 128`，两层均接 ReLU | 英雄与地图嵌入直接参与融合，同时通过门控影响上下文 |
| 输出头 | Actor：`128 → 16`；Critic：`128 → 1` | 分别输出动作 logits 与状态价值 |

例如同一地形下怪物和资源信息变化时，五个上下文分支的编码随之变化；门控权重则由英雄与地图嵌入计算。当前没有保存逐状态门控权重，因此无法给出具体场景中的分支关注度。

动作共 **16 个**：0–7 依次向东、东北、北、西北、西、西南、南、东南移动；8–15 向同样八个方向闪现。网络输出 logits 后，智能体结合环境的 16 维合法动作掩码生成概率；训练随机采样，验证取概率最大值。掩码主要反映技能可用性，普通移动被标为合法仍可能撞墙。

模型共 **75,814 个参数**。归档权重含 **44 个张量**，已与现有网络严格匹配，并通过数值与前向输出检查。完整形状、模块参数分布和奖励公式见[方法说明](docs/method.zh-CN.md)。

## 奖励设计

单步训练奖励是各项增量之和，用于同时反馈得分、风险与动作质量；比赛榜单仍使用前述环境分数。

![训练奖励中的事件增量](docs/figures/rewards.zh.svg)

| 类别 | 关键数值与条件 | 设计对应的行为 |
|---|---|---|
| 得分与资源 | 正常存活一步约 +0.03；每个宝箱 +1.20；拾取 BUFF +0.35 | 延长生存并收集资源 |
| 避险与地形 | 怪物距离增量系数 0.10、危险度下降系数 0.12、夹击缓解系数 0.08；死胡同与贴墙为负项 | 拉开距离、缓解双怪夹击并避开不利地形 |
| 目标推进 | 宝箱接近系数 0.015，仅在危险度 <0.35 且未拾取宝箱时生效；BUFF 接近系数 0.012，另受效果状态与目标距离限制 | 在风险较低时推进目标 |
| 动作质量 | 位移 <0.1 时 -0.03；安全、无资源收益且 10 个位置窗口内首尾距离 <5 时 -0.10 | 对撞墙及小范围徘徊提供反馈 |
| 闪现质量 | 高危有效脱险 +0.20，否则 -0.12；中危有效脱险且更开阔 +0.08，否则 -0.04；低危安全取宝 +0.04，否则 -0.05 | 根据施放前风险、距离变化、危险度变化与地形变化评价闪现 |
| 终局 | 被捕获 -2.00；达到步数上限 +1.20；异常截断 -0.50 | 区分不同结束状态 |

表中系数仍需乘距离变化、风险或地形量；多个事件可在同一步叠加。闪现“有效脱险”是奖励判定条件。上述数值是代码配置，完整公式及阈值见[奖励塑形](docs/method.zh-CN.md#5-奖励塑形)。

## 技术流程与训练

![训练与验证流程](docs/figures/workflow.zh.svg)

1. **形成状态**：每局重置缓存与行为历史；预处理当前环境观测，计算局部 BFS、资源目标、风险、地图与记忆，再展平为 3601 维输入。
2. **决策与交互**：网络输出动作 logits 和价值 `V(s)`，掩码后采样动作。环境执行动作，下一帧预处理按本次变化计算训练奖励。
3. **记录轨迹**：保存当前状态、掩码、动作、奖励、结束标志、旧价值和完整旧动作概率。整局结束后向后递推 GAE，得到优势 `A` 与价值目标 `A + V`；末步下一状态价值置零。
4. **更新模型**：轨迹发送至平台样本池，Learner 取 512 条样本并标准化优势，按 mini-batch 256 进行 4 轮 PPO 更新。采样器从池中均匀取样，旧样本按 FIFO 移除。
5. **同步与验证**：平台配置每分钟同步模型；训练工作流在新局开始加载 `latest`。地图 9、10 使用最大概率动作，每轮共 4 局，只上报 `val_*` 均值；验证轨迹不进入样本池。

GAE（广义优势估计）结合奖励、当前/下一状态价值和后续反馈，衡量动作结果相对价值预期的差异。PPO 用所选动作的“新概率 / 采样时旧概率”构造策略目标，剪切范围为 `[0.8, 1.2]`，用于限制过大概率变化带来的目标收益；Critic 拟合 `A + V`，熵正则鼓励保留动作探索。

联合损失为 `L = L_policy + 0.5 L_value − 0.005 H(π)`；代码中的 `L_value` 已含 `0.5 × max(普通平方误差, 剪切后平方误差)`。策略与价值剪切、优势标准化和梯度裁剪的具体计算见[PPO 与样本](docs/method.zh-CN.md#4-ppo-与样本)。

| 环境 | 归档配置 | PPO | 归档配置 |
|---|---|---|---|
| 训练 / 验证地图 | 1–8 / 9、10 | γ / GAE λ | 0.99 / 0.95 |
| 宝箱 / BUFF 数量 | 10 / 2 | Adam 学习率 | 3 × 10⁻⁴ |
| BUFF 刷新 / 闪现冷却 | 200 / 200 步 | 策略与价值剪切范围 | 0.2 |
| 第二怪物 / 怪物加速 | 200 / 300 步 | 熵系数 / 价值系数 | 0.005 / 0.5 |
| 单局上限 | 1000 步 | 更新轮数 / mini-batch | 4 / 256 |
| 轻量验证 | 每轮共 4 局，间隔 600 秒 | Learner 批次 / 样本池 | 512 / 2048 |

训练监控分别记录环境分数、整局塑形奖励、存活步数、宝箱数和终局状态，优化侧记录损失、熵与概率比等诊断量，字段解释见[指标字典](data/metadata/metrics.csv)。上表 600 秒是验证间隔配置；首轮因计时初值为 0，在首个训练局后即可触发。

原始轻量验证对同帧有重复预处理，环境怪物加速为 300 步而部分特征/奖励参考阈值为 500 步。BFS 只提供局部近似可达性，预处理器的 8 邻域搜索未完整约束对角移动。具体语义见[实现边界](docs/method.zh-CN.md#7-实现边界)；历史验证结果未留存。
